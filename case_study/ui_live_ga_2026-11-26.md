# UI pass: a real coding task through the console (2026-11-26)

**What was tested:** one real task done end to end through the console, driven in Chrome's debug mode, with no verbs or CLI calls. The task was a static HTML study guide for the OMSCS CS6515 (Graduate Algorithms) cumulative multiple-choice final, built from links prefetched for the worker.

- **Recipe:** `tools/ui_drive.py`. It types the request on Home, picks the template, starts the draft, fills the form, clicks Sign and follows the run page until it ends. It screenshots on every status or step change and every 5 minutes, and records a timeline. At the end it renders what the worker made, at desktop and phone widths.
- **Inputs:** `sandbox/ga-final-guide/refs/LINKS.md` (7 prefetched sources with one-line summaries: the Fall 2026 syllabus, the OMSCS course page, Vigoda's lecture outline, two student reviews, flashcards, and a comparable final review). The request said to start from those links, cover every unit with key facts, running times, multiple-choice traps and self-check questions, and produce one self-contained file readable on a phone.
- **Settings:** template `coding` (one step, "Do the task"); model qwen3.6-35b-a3b; trigger "Once, now".
- **Artifacts:**
  - Screenshots, `timeline.jsonl` and `findings.json`: `case_study/ui/live_ga/`.
  - The guide: `case_study/ui/live_ga/made/index.html`.
  - Rerun with: `.ariadne/ga_drive.ps1` (not in git).

## What worked as intended

- The full path from Home to Sign works from the page alone in 11 s: start box, template choice, draft form, Save, Sign, run page.
- While the run works, the page shows its activity: each search, each read, each file written, and the tool, model and file counts. The machine bar names the run and the model.
- The result renders on the run page, and Files changed shows `index.html`.

## Bugs found and fixed (in this commit)

1. **A "Once, now" task re-ran forever.**
   - **Cause:** `spec.next_due()` treated `now` as due at whatever time it was asked. Signing starts the one run directly, but the scheduler also found the task due. So every time the machine freed up, another run was queued: `r1126-042950-5276`, then `r1126-043141-da08`.
   - **Fix:** `now` (like `manual`) has no next due time.
   - **Regression test:** `test_a_run_once_now_task_runs_once`.
2. **A cancelled run stuck as "running" when its worker died.**
   - **Cause:** the worker restarts itself between runs when the code changes (it did, after fix 1). The console was also restarted while a cancel was pending. The worker's startup check returned live runs to the person as needs_you and ignored the pending cancel.
   - **Fix:** `daemon.reconcile` now marks a run cancelled if the person had asked to cancel it.
   - **Regression test:** `test_a_dead_worker_leaves_cancelled_what_you_cancelled`.

## Open UI issues (not fixed)

- **A long model call is invisible.** For the 8-minute writing call, "Now:" showed the previous call ("model call 6 … 6 min ago") while "Last activity" read "1 s ago". A model event is only recorded when a call ends. The page should show "model call 7 in progress, N min" from the moment a call starts.
- **The orchestrator panel looks like a chat that never answered.** On the draft page, the request shows as a chat bubble with no reply, because nothing asks the orchestrator unless you write to it. Either label the bubble as the request, or let the orchestrator acknowledge it.
- **The coding template has no check gate.** "Do the task" is a single step, so nothing outside the worker checked the result. The investigation template's gates (W-recipe) would have caught the issues below.

## The study guide: what the worker produced

- **Shape:** one 684-line, 38 KB self-contained file with inline CSS and no scripts. It has 9 sections with a sticky nav: exam format, then DP, D&C, randomized algorithms and RSA, graphs, max-flow, LP and NP. It has 16 multiple-choice traps, 18 self-check questions with answers in `<details>`, and a sources section.
- **Correct (spot-checked):**
  - Knapsack O(nW) as pseudo-polynomial.
  - Karatsuba and Strassen exponents; FFT O(n log n).
  - Ford-Fulkerson O(C·|E|) and Edmonds-Karp O(V·E²), with the BFS argument.
  - The min-cut read off the residual graph.
  - 2-SAT via SCCs; Kosaraju/Tarjan O(V+E).
  - LP in P vs ILP NP-complete; unbounded primal means infeasible dual; the dual of the dual is the primal.
  - Fermat vs Carmichael numbers; LCS("ABCBDAB", "BDCAB") = 4.
- **Wrong or off-course:**
  - **Invented exam split.** The topics per exam ("Exam 4 (Review / practice)") are made up; the syllabus does not say.
  - **Duality convention backwards for this course.** Weak duality is stated for a *min* primal (primal ≥ dual), and the trap says "don't flip the sign". CS6515 and DPV state it for a max primal (primal ≤ dual), so the trap teaches the opposite of the lectures.
  - **Wrong topics in D&C.** Median of two sorted arrays and closest pair are not course topics. Median-of-medians (linear-time selection), a staple of the unit, is missing.
  - **Gaps.** The halting problem / undecidability is missing, and so is knapsack as an NP-complete problem.
  - **Small errors:**
    - matrix-chain appears twice in the DP table, citing "DPV Ch. 3" (it is ch. 6);
    - the knapsack space is given as O(W) for the basic table;
    - the Master Theorem case-1 exponent renders garbled;
    - the phone render is wider than the screen (458 px vs 390 px; the tables and code blocks overflow).
- **Verdict:** a usable first draft for revision that looks finished but would mislead on duality. In terms of `docs/WORKER-RECIPE.md`, this is W3 (it filled an ambiguous convention its own way: duality) and W10 (no read-only reviewer was the last gate, so nothing compared the guide with the syllabus and lecture outline). Next time, run this kind of task on the investigation template, or add a review gate that checks topics against the syllabus and lecture outline.

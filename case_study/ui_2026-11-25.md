# Case study: the UI in Chrome's debug mode, 25 November 2026

**How it was tested.** `tools/ui_case.py` starts Chrome with its own throwaway profile and
`--remote-debugging-port`, and drives `ariadne ui` over the DevTools protocol. It visits each view (home, a task,
the live googl-daily run, an ended run, the run's activity log) at desktop (1440x900) and phone (390x844) widths and
in dark mode, screenshots each, and records every console message, page error, failed request and 4xx/5xx response.
It also checks for sideways scrolling and unlabeled controls. The Claude in Chrome extension was not connected, so
the protocol was driven directly: the same debug mode Ariadne's workers use for the browser.

Screenshots: `case_study/ui/shots/` (before) and `case_study/ui/shots-after/` (after the fixes), each with
`findings.json`.

**Verdict.** Clean: no page errors, no failed API calls and no sideways scrolling at any width or in either theme.
The one 404 was the favicon. What it lacked was visibility into the work, which is what the person asked for.

## Findings and fixes (e8d3a18)

| Seen | Fix |
|---|---|
| What a worker writes and runs was hidden behind "Show the activity" | The running step lists its latest tool calls, job output, and looping or quiet notes inline, under the step |
| An ended run still showed its interrupted step as "running" | A step cut off when its run ended reads "stopped" |
| The orchestrator panel showed only "Thinking..." for minutes | It lists the orchestrator's waits, model calls and tool calls while the turn works (new `chat_activity` verb) |
| The steer box placeholder was cut off on a phone, and the hint said notes reach only the next boundary | "A note for this run"; the hint says a note holds for every later step |
| `favicon.ico` 404 on every first load | An inline icon (the thread) |

From the earlier commits of the same evening, the run view also gained a live "Now:" line (the last tool or model
call and how long ago), and the run's events return the newest rather than the oldest 500.

## Before and after

- Before: `shots/run-live-desktop.png`, the run showed "Now: step 1: model call 1" and nothing about its files.
- After: `shots-after/run-live-desktop.png`, step 1 lists "wrote NOTES.md", "read NOTES.md" under itself.
- Before: `shots/run-needs_you-desktop-dark.png`, step 5 "running" on a run that ended.
- After: `shots-after/run-needs_you-desktop-dark.png`, step 5 "stopped".

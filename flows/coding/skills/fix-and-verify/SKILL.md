# Fix and verify

1. Read before you change: open the files the task names and the tests that cover them. Recall shared memory
   for the repository (memory_recall with the repo path) - earlier tasks may have recorded conventions.
2. Make the smallest change that does the job. Keep the existing style. Do not reformat unrelated code.
3. Prove it: run the repository's tests (`python -m pytest -q` when there is a tests folder) and read failures
   to the end before changing anything else.
4. Commit locally with git_add and git_commit: a one-line imperative message saying what changed. Never push.
   Never add co-author or "generated by" lines.
5. Record in shared memory what the next task should know (memory_record kind=repo, name=<repo path>).
